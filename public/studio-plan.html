Content Studio

재료를 만들고, 가공하고, 바로 확인하는 웹 제작 작업공간

공통 기반 + 제작 도구 하나 + 렌더러를 연결해 실제 편집 흐름을 검증한다.

01 / 공통 기반

에셋 · 문서 · 명령

이미지 Blob과 편집 문서를 분리하고, 사용자와 에이전트용 명령에 같은 검증을 적용한다.

02 / 첫 도구

2D 장면 배치

이미지·도형의 위치, 크기, 순서, 색상과 클릭 동작을 편집한다.

03 / 렌더링

Three.js + R3F

같은 문서를 편집 화면과 실행 미리보기에서 렌더링한다. 변경 즉시 반영한다.

원본 에셋→편집 문서→명령·검증→실행 미리보기→수정·저장↺편집 변경은 빌드 없이 즉시 반영

S0

범위와 데이터 계약

완료

엔진 독립 문서 v1, 에셋 ID와 참조, 검증된 명령 배치, 이번 단계의 한계를 기록한다.

완료 기준 · 문서·도구·렌더러 경계를 코드와 계획에 명시한다.

공통 저장과 교환

완료

SHA-256 이미지 식별, IndexedDB 원자적 저장, 다른 탭의 덮어쓰기 감지, 이미지 포함 번들 가져오기·내보내기.

완료 기준 · 새로고침과 번들 재가져오기 후 장면과 이미지가 유지된다.
S2

완료

완료 기준 · 화면 조작과 JSON 명령이 같은 결과를 만들고 잘못된 명령은 원본을 변경하지 않는다.

완료 기준 · 검증 근거와 남은 한계를 이 계획 및 README에 반영한다.

완료 기준 · 앱 번들 생성 및 실행 프로세스 확인.
S4c

새 게임과 동적 제작 도구

예정

새 게임에서 템플릿을 독립 폴더로 복제하고 기존 에이전트 작업공간에 연결한다. 필요한 도구를 호출해 산출물을 게임 문서에 적용한다.

완료 기준 · 템플릿 복제 → AI 제작 → 도구 호출 → 결과 적용 → 미리보기 흐름을 실제 프로젝트로 검증한다.
S5

서버 저장과 에이전트 연결

예정

워크스페이스별 Blob 저장, 영속 버전, 파일 감지, MCP 명령 연결, 다중 사용자 충돌 처리.

완료 기준 · 에이전트의 변경을 사용자가 즉시 확인하고 같은 이력에서 되돌릴 수 있다.
S6

제작 공정과 분야별 확장

예정

가공 작업·의존성·캐시·재생성, 타일맵, 3D 지형·재질·내비게이션, 타임라인·강의 단계.

완료 기준 · 원본 변경의 영향을 추적하고 필요한 산출물만 재생성한다.

이번 단계의 경계

  • 이번 저장 범위는 이 브라우저·origin의 초안 하나다. 서버·폴더별 저장과 공동 편집은 아직 없다.
  • 실행 취소 이력은 현재 세션의 최대 50단계다. 영속 에셋 버전·공정 이력은 후속 단계다.
  • 에이전트는 번들과 명령 JSON을 편집할 수 있다. 실시간 MCP 도구 노출은 아직 없다.
  • 미리보기는 실제 Three.js 렌더링이다. 독립 배포용 콘텐츠 플레이어 내보내기는 후속 단계다.
  • 이미지당 10 MB, 장면 이미지 합계 20 MB, 객체 200개로 첫 검증 범위를 제한한다.
  • UI는 한국어와 영어를 제공한다. 다른 앱 언어에서는 이번 기능만 영어로 표시한다.
  • 새 게임 템플릿 복제·AI 자동 제작·동적 도구 호출은 아직 구현 전이다.

설계 결정

D01
게임을 첫 적용 분야로 삼는 범용 콘텐츠 제작 플랫폼

같은 재료와 편집 공정을 인터랙티브 웹·강의·시뮬레이션에서도 사용한다.

D02
첫 렌더러는 Three.js + React Three Fiber

현재 React 구조에 연결하며, 게임 동작과 분야별 기능은 별도 모듈로 추가한다.

D03
첫 제작 도구는 2D 장면 배치

원본 이미지 → 배치 → 클릭 동작 → 저장·다시 열기의 최소 전체 흐름을 빨리 검증한다.

D04
편집 문서와 런타임 객체 분리

렌더러 교체, 에이전트 편집, 데이터 검증, 실행 취소의 기준을 문서와 명령으로 유지한다.
